# 设计

## 解析与数据模型

词法读取和递归下降解析共享一个位置游标。读取条目前检查全局条目上限，进入对象前检查深度，读取字符串时检查 token 长度。错误携带稳定类别和当前位置，不猜测损坏输入的缺失结构。

使用 `Array[Entry]` 保留顺序与重复键；JSON 导入和导出沿用同一结构。`get`、`get_all` 和 `lookup` 的重复键选择规则分别固定，避免调用者依赖偶然的字典覆盖行为。`Selector` 使用键及出现次数定位编辑对象。

写出器负责统一缩进和字符串转义。解析—写出—重读的目标是结构等价。`SourceDocument` 另行记录 Unicode 标量范围，局部编辑拼接修改前后的原文，并重新解析核对语义；普通解析不记录这些范围。

平台条件以调用方提供的符号集合求值，不推测运行平台。文件引用接受显式回调，维护活动文件栈、累计字符数和条目数。二进制编解码使用独立类型模型，数字不经过浮点或 JSON 数值转换。

## Steam 层

Steam 模型只解释已经解析的文档，不读取本机数据。应用 ID 和构建 ID 保留十进制字符串；SizeOnDisk 使用受溢出检查的 Int64，CLI 导出时转成字符串。

## IO 与命令行

核心库和示例不含 FFI。JavaScript 宿主使用 Node.js；原生宿主通过小型 C 适配提供有上限的字节读取、普通文件枚举及标准流访问。原生 UTF-8 解码、路径组合、KV1 解析、查询、规范化、Steam 解释及清单分析由 MoonBit 完成。

inventory 对各个库和清单分开处理错误。成功的游戏记录与失败信息一起返回，出现部分失败时使用退出码 1。命令只读取输入文件。

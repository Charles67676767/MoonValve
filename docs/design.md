# 设计

## 解析与数据模型

词法读取和递归下降解析共享一个位置游标。读取条目前检查全局条目上限，进入对象前检查深度，读取字符串时检查 token 长度。错误携带稳定类别和当前位置，不猜测损坏输入的缺失结构。

使用 `Array[Entry]` 保留顺序与重复键；JSON 导出沿用同一结构。`get`、`get_all` 和 `lookup` 的重复键选择规则分别固定，避免调用者依赖偶然的字典覆盖行为。

写出器负责统一缩进和字符串转义。解析—写出—重读的目标是结构等价，原始注释和空白不在当前数据模型内。

## Steam 层

Steam 模型只解释已经解析的文档，不读取本机数据。应用 ID 和构建 ID 保留十进制字符串；SizeOnDisk 使用受溢出检查的 Int64，CLI 导出时转成字符串。

## IO 与命令行

核心库和最小示例不含 FFI。Node.js 宿主只提供有上限的文件读取、严格 UTF-8 解码、目录枚举及标准流访问。KV1 解析、查询、规范化、Steam 数据解释及清单汇总由 MoonBit 完成。

inventory 对各个库和清单分开处理错误。成功的游戏记录与失败信息一起返回，出现部分失败时使用退出码 1。命令只读取输入文件。
